# Пакетный датасет RoofCheck: много фотографий, OpenCV, без весов

## Назначение

`tools/build_classic_roof_dataset.py` рекурсивно обрабатывает JPG/JPEG/PNG/TIFF/WEBP/BMP. Он не запускает нейросети. Для каждой фотографии делает **несколько** независимых кандидатов крыш; при явно подтверждённом бесснежном источнике может вызвать `python -m roofcheck.roof` и получить несколько синтетических снежных изображений на кандидата.

**ВАЖНО:** обнаруженные по OpenCV кровли и скаты являются *непроверенными предложениями*. Автоматический результат НЕ считается истинной разметкой и не должен использоваться в val/test. Экспортированный датасет имеет статус `train_candidate`, пока эксперт не просмотрит изображение и соответствующую маску. Все модели, оценки и примеры тут относятся к **синтезу снега на фото**, а не к детекции снега.

## 0. Установка

Из корня репозитория `RoofCheck` после применения standalone-патча:

```bash
python -m pip install numpy scipy pillow opencv-python-headless
python tools/build_classic_roof_dataset.py --help
```

Детектору не нужны PyTorch и веса. Для запуска рендеринга исходный модуль `roofcheck.roof` уже должен присутствовать в `RoofCheck`.

Исходные фотографии должны быть доступны по локальному пути. Поместите набор, например, в `/data/roofs_clean/`; выходной каталог должен находиться **вне** него.

## 1. Безопасный короткий пробный запуск на первых 10 фото

```bash
python tools/build_classic_roof_dataset.py \
  --input "/data/roofs_clean" \
  --output "/data/roofcheck_trial" \
  --max-images 10 \
  --max-roofs 3 \
  --min-confidence 0.68
```

Без `--render` программа сохраняет только предложения `samples/img_*/proposals/roof_*/` с `overlay.jpg`, `roof_mask.png`, `occluder_mask.png`, `sample.json`, `cvat_proposals.xml` и прочим. `manifest.csv` будет пустым, потому что синтетические изображения ещё не создавались. Это полезный этап оценки ошибок на конкретной камере.

Оцените качество, особенно **пиксели вне крыши**, пропущенные окна и серые/тёмные кровли. `--include-neutral` увеличивает полноту поиска, но значительно увеличивает риск ложных крыш.

## 2. Большая папка: получить изображения со снегом и маски

Это допустимо, только если **каждая исходная фотография действительно бесснежная**. Флаг `--verified-clean` означает подтверждение человеком, а не автоматическую проверку:

```bash
python tools/build_classic_roof_dataset.py \
  --input "/data/roofs_clean" \
  --output "/data/roofcheck_synthetic_v1" \
  --verified-clean --render \
  --max-roofs 5 \
  --variants 4 \
  --min-confidence 0.68 \
  --include-clean-controls \
  --keep-proposals
```

По умолчанию 4 варианта на крышу: покрытия 8%, 35%, 65%, 92%, сценарии `sparse_patches`, `partial_cover`, `cleared_irregular`, `near_full_cover`. Можно указать другие параметры:

```bash
--variants 3 --coverages 0.1,0.5,0.9 \
--scenarios sparse_patches,partial_cover,near_full_cover
```

Если у фото обнаружено 2 подходящие крыши, это до 2×4 снежных кадров плюс 2 чистых контрпримера. Параметр `--max-roofs` ограничивает число обработанных кандидатов с максимальным эвристическим баллом, **но не удостоверяет, что это реальные крыши**.

Чтобы возобновить после прерывания, повторите **тот же вызов** и добавьте:

```bash
--resume
```

Изменять параметры уже начатого запуска нельзя. Сначала выберите `--max-images 10` в пробном отдельном каталоге; для большого запуска используйте новый каталог без `--max-images`. Ошибки отдельных фото пишутся в `progress.jsonl` и не останавливают остальные изображения. Неуспешные фото повторно обрабатываются при `--resume`.

**При ошибке одного варианта рендеринга текущая фотография считается неуспешной целиком**, чтобы не включать частичный, потенциально несогласованный набор. До успешного повтора в основной `manifest.csv` она не попадёт.

## 3. Структура результата

```text
roofcheck_synthetic_v1/
    config.json
    progress.jsonl
    summary.json
    manifest.csv              # ВСЕ непроверенные пары изображение/маска
    review.csv                # решение эксперта для каждой пары
    samples/
        img_<стабильный-хеш-пути>/
            records.json
            roof_001/
                v000/image.png, mask.png, roi.png, metadata.json
                v001/image.png, mask.png, roi.png, metadata.json
                ...
                clean/image.png, mask.png, roi.png, metadata.json
            proposals/roof_001/
                overlay.jpg, roof_mask.png, occluder_mask.png,
                sample.json, cvat_proposals.xml, detection.json, ...
```

`mask.png`: **uint8, значения 0 (нет снега), 1 (снег), 255 (неизвестно/исключено)**. Эти PNG не надо преобразовывать в белые 0/255 маски при обучении. `roi.png` помогает оценивать качество в пределах выбранной кровли. `group_id` одинаков для производных одного исходного снимка, чтобы исключать утечку между train/val/test. Все автоматически созданные примеры относятся только к `train_candidate`.

`--keep-proposals` экономно отключать для больших запусков **после** проверки алгоритма, потому что он хранит копии источников для каждого кандидата. Без него сохраняются только пары, метаданные и журнал. На тысячах фотографий предусмотрите достаточно места; размер итогового набора пропорционален числу крыш, вариантов и разрешению.

## 4. Экспертная проверка и экспорт обучающего набора

Откройте `samples/<id>/<roof_*>/v*/image.png` рядом с `mask.png`. Проверьте, не вышел ли синтетический снег на фасад, землю, чужую крышу или окно, и совпадает ли маска с видимым снегом. Затем в `review.csv` заполните:

- `decision=accept` или `reject`;
- `reviewer=...` для каждого `accept`;
- при необходимости `note`.

Команда ниже **не примет** записи с пустым `decision` и не позволит автоматически принять всё без проверки:

```bash
python tools/approve_classic_roof_dataset.py \
  --run "/data/roofcheck_synthetic_v1" \
  --output "/data/roofcheck_train_reviewed_v1"
```

Результат: `train/images/*.png`, `train/masks/*.png`, `train/roi/*.png`, `manifest.csv` и `dataset_card.json`. Это только TRAIN. Для обучения/оценки `val` и `test` нужны **реальные** снимки крыш, размеченные независимо; нельзя проверять качество сегментатора снега на этой же синтетике.

## 5. Ограничения и проверка

- OpenCV не даёт гарантию, что неизвестная крыша или скат будет найдена правильно. Ошибки разметки превращаются в ошибки обучения.
- Нельзя включать `--verified-clean` на смеси бесснежных и заснеженных изображений.
- Не смешивайте несколько ракурсов одного объекта между train/val/test.
- Для 4000×3000 фотоснимков начните с `--max-images 10`, `--max-roofs 2` и `--variants 2`: рендерер и экспорт масок требуют существенной оперативной памяти и диска.
- Если фото содержит много обычных серых крыш, данный классический алгоритм может не дать пригодный результат. Можно попробовать `--include-neutral`, но он пока экспериментальный.

Синтетические проверки:

```bash
python -m unittest discover -s tests -p 'test_classic_batch.py' -v
```

В тесте рендерер замещается заглушкой, поэтому он проверяет интерфейс, сохранение и подтверждение результатов, **но не гарантирует успешный рендеринг всего `roofcheck.roof` на реальных данных**. Перед многотысячным запуском обязательно выполните 10-файловый пробный прогон с `--render`.
