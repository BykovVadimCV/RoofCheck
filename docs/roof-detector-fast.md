# Ускорение RoofCheck без нейросетей: сжатие и обрезка по крыше

Этот апдейт расширяет `tools/build_classic_roof_dataset.py` и совместим с предыдущим
режимом (`--work-max-side 0 --roof-crop-pad 0`, значения по умолчанию).
Ни PyTorch, ни нейровеса не нужны.

## Где теряется время

На снимке 2048x1536 = 3 145 728 пикселей. Детектор OpenCV уже выполняет
сегментацию на уменьшенной копии, но старый пакетный код **каждую** крышу
и **каждый** вариант снега рендерил на полном RGB. Важное различие:
`--max-side` уменьшал только временный массив детектора, **не** вход рендерера.
Также `write_detection` заново создавал полные карты всех крыш для каждого кандидата.

## Новые параметры

- `--work-max-side 1024`: уменьшить входное фото **до детектора, масок и
  генератора** (максимальная сторона 1024 пикселя). Без указания 0 / исходное
  разрешение. Маски создаются сразу в новой системе координат, а не
  масштабируются независимо после генерации.
- `--roof-crop-pad 64`: для каждой крыши вырезать её bounding box плюс запас
  64 пикселя по каждой стороне. `roof_mask`, `occluder_mask`, `surfaces` и
  `sample.json` пересчитываются относительно кропа. Без указания 0, кроп не
  применяется. Прямоугольник кропа и исходный размер зафиксированы в
  `detection.json`.
- `--work-jpeg-quality 90`: сжатие временных RGB для ресайза и кропа. **Маски
  остаются PNG** без JPEG-артефактов.
- `--no-ridges`: пропустить относительно дорогие эвристические линии конька.
  Используется цельный скат-предложение, без обещания геометрической точности.
- `--max-roofs 2 --variants 2`: ограничить число тяжёлых вызовов рендеринга.

## Пробный запуск на 10 изображениях (сначала БЕЗ рендера)

```bash
python tools/build_classic_roof_dataset.py \
  --input "/data/roofs_clean" \
  --output "/data/roof_fast_preview" \
  --max-images 10 --max-roofs 2 \
  --work-max-side 1024 --roof-crop-pad 64 \
  --no-ridges --keep-proposals
```

Проверьте `samples/img_*/proposals/roof_*/overlay.jpg` и
`roof_mask.png` / `occluder_mask.png`. Сначала на типичных серых крышах:
классический цветовой детектор может не найти их вовсе.

## Быстрая генерация датасета (только подтверждённые бесснежные источники)

```bash
python tools/build_classic_roof_dataset.py \
  --input "/data/roofs_clean" \
  --output "/data/roof_fast_dataset_v1" \
  --verified-clean --render \
  --work-max-side 1024 --roof-crop-pad 64 --work-jpeg-quality 90 \
  --no-ridges --max-roofs 2 --variants 2 \
  --include-clean-controls
```

Для максимальной скорости на пилоте можно попробовать `--work-max-side 768`
и `--roof-crop-pad 48`. Для последующего обучения на текстуре швов/тонком
снеге лучше 1280+ и оставить запас вокруг крыши. При нескольких соседних
крышах кроп может обрезать часть контекста, но исходный путь и исходное
разрешение остаются в метаданных/манифесте.

`--resume` работает только с прежним набором настроек: при переходе на
уменьшенные изображения обязательно используйте **новый** выходной каталог.

## Реально измерено на DJI_0477.jpg

Проверка **только стадии поиска/экспорта двух предложений, без генерации снега**
(один прогон, локальное тестовое окружение, `--no-ridges`):

| Режим | Wall time | Peak RSS | Размер папки proposals |
|---|---:|---:|---:|
| Полные 2048x1536 | ~2.03 c | ~336 MB | ~5.3 MB |
| 1024 + кроп 48 px | ~1.16 c | ~175 MB | ~204 KB |

Это **не** результат полного `--render`. Приблизительное снижение числа
обрабатываемых рендерером пикселей в 4 раза от ресайза НЕ гарантирует
4-кратный выигрыш по времени: есть постоянные издержки, повторная инициализация
процессов и зависящие от содержимого вычисления. Кроп часто даёт более
существенный выигрыш, когда крыша занимает небольшую часть кадра.

## Ограничения

- `--work-max-side` физически уменьшает детали, мелкие трубы и фальцы могут
  перестать различаться. **Не использовать как единственную разметку**.
- `--roof-crop-pad` меняет состав итоговых обучающих изображений: это
  фрагменты сцен, а не исходные городские панорамы. Сохраняйте часть full-view
  примеров для обучения и проверки устойчивости модели.
- Маска, согласованная с уменьшенным RGB, не делает детектор точнее. Для
  сложных тёмных/серых крыш без нейросетей по-прежнему требуются выборочная
  ручная проверка и отбраковка.
- В варианте большого датасета **не** используйте одновременно смешанный
  зимний/летний набор с `--verified-clean`: программа не определяет отсутствие
  исходного снега автоматически.
- Для безопасной проверки запуска рендерера начните с `--max-images 1
  --max-roofs 1 --variants 1` в отдельном выходном каталоге.

## Проверки

```bash
python -m unittest discover -s tests -p 'test_classic_batch.py' -v
```

Тестирует размер/EXIF-ориентацию входа, согласованность масок после уменьшения
и кропа, целостность обучающих 0/1/255 меток, clean-control и `--resume`.
Рендерер в unit-тесте замещён заглушкой. Реальную скорость `roofcheck.roof`
следует измерить отдельно на машине пользователя с установленным проектом.
