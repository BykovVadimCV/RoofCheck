# RoofCheck: автоматические предложения крыш без нейросетей

## Что реализовано

`roofcheck/roof_detection/classical.py` использует только NumPy, SciPy и OpenCV:

1. Приведение RGB-фотографии к рабочему масштабу (маски экспортируются обратно в исходные EXIF-ориентированные координаты).
2. Поиск тёплых оттенков черепицы (HSV + отношения R/G/B) и проверка локальной плотности окрашенных пикселей. Это снижает количество случайных красноватых пятен на дороге.
3. Морфологическое восстановление контура, фильтрация связных компонентов по размеру и форме.
4. Поиск замкнутых небольших дыр внутри цветной кровли. Такие области **предлагаются как препятствия** (например, мансардные окна), но не считаются доказанными объектами.
5. Поиск длинных отрезков через OpenCV LSD. Линия предлагается в качестве разделителя скатов **только если** она пересекает область и создаёт две достаточно большие части.
6. Экспорт **каждой предложенной крыши отдельно** в формат текущего `roofcheck.roof` плюс CVAT и карты идентификаторов.

Ни один из этих пунктов не применяет ML-модель или не загружает веса. `model_info.backend` равен `classical-opencv`; `confidence` представляет **эвристический балл**, а не вероятность точной сегментации.

## Установка

Из корня клонированного репозитория `RoofCheck` применить **самостоятельный патч без нейросетей**, если предыдущая интеграция детектора ещё НЕ установлена:

```bash
# Зафиксировать или убрать собственные незакоммиченные изменения.
git switch -c feat/classical-roof-detector
git apply --check /path/to/roofcheck_classic_standalone.patch
git apply /path/to/roofcheck_classic_standalone.patch
python -m pip install numpy scipy pillow opencv-python-headless
```

Если пять этапов предыдущего детектора уже установлены, применить **только дополнительный** `roofcheck_classic_stage6.patch`. Не применять оба патча одновременно. Для установки классического и опционального нейросетевого backends из чистого `main` имеется альтернативный `roofcheck_classic_combined.patch`. Он не нужен для режима OpenCV.

## Запуск без весов и выбора точки

```bash
python tools/detect_roof_classic.py \
  --image DJI_0315.jpg \
  --output out/classic_DJI_0315 \
  --min-area 850 \
  --min-confidence 0.68 \
  --max-roofs 20
```

В этой самостоятельной CLI утилите используется только OpenCV. При запуске без `--target-point`, `--target-bbox`, `--reference-mask` и `--all` автоматически включается покрышный экспорт: создаётся **одна независимая папка на каждую обнаруженную область**, без угадывания «главной» крыши. Папки: `out/classic_DJI_0315/roof_001/`, `roof_002/` и т. п. В корне находится `summary.json`.

В каждой папке есть:

- `roof_mask.png`: выделенная область кровли, 0/255;
- `occluder_mask.png`: предполагаемые препятствия, 0/255;
- `snowable_mask.png`: диагностическая разность «кровля без препятствий»;
- `roof_instance_ids.png`, `facet_instance_ids.png`: карты предложений 16-бит;
- `cvat_proposals.xml`, `cvat_labels.json`: проект предварительной разметки;
- `detection.json`, `overlay.jpg`: объяснимость и просмотр;
- `source.jpg` и `sample.json`: вход в действующий генератор.

### Попробовать более рискованный поиск серых крыш

```bash
python tools/detect_roof_classic.py \
  --image DJI_0315.jpg --output out/classic_DJI_0315_neutral \
  --include-neutral --min-confidence 0.30
```

Это **экспериментальный** поиск нейтральных замкнутых четырёхугольников с цветовым контрастом. Он может принимать за крыши фасады, дворы или прочие плоскости. На `DJI_0315.jpg` он **не нашёл** крупную плоскую серую крышу должным образом; использовать его как проверенную разметку нельзя.

### Генерация снега

Если исходное фото **проверено как бесснежное**, можно отдельно подтвердить это:

```bash
python tools/detect_roof_classic.py \
  --image clean.jpg --output out/classic_clean \
  --verified-clean --render --max-roofs 6
```

`--verified-clean` является утверждением оператора об исходном фото. Система **не определяет наличие снега автоматически**: это отдельная задача, которую здесь намеренно не решаем. Если не передать `--verified-clean` или экспертную `--snow-mask`, то `sample.json` содержит `annotation_mode=partial`, и неизвестные пиксели остаются неизвестными, а не превращаются в «чистую крышу».

Если необходимо обработать только конкретную поверхность, можно передать `--target-point X Y`. Это **не обязательно** для автоматического покрышного экспорта.

## Ограничения и принятие результата

Это рабочий **классический детектор-предложитель**, но не гарантированный универсальный распознаватель крыш. На одном RGB-кадре без эталона и без обученных семантических моделей невозможно надёжно отличить всякую тёмную кровлю от фасада, площадь крыши от земли, шов фальца от конька или заметить все дымоходы и стеклянные окна. Поэтому:

- маска *не должна автоматически попадать* в train/val/test как экспертная истина;
- перед использованием синтетики в обучении нужно проверить геометрическую точность маски и препятствий на каждом фото или хотя бы в надёжной процедуре QA;
- автоматическое разделение скатов остаётся **предложением**, а не измеренной 3D-геометрией;
- размеры сеток в `sample.json` задают канонические координаты для рисунка снега, а не метры;
- на нескольких зданиях алгоритм выдаёт независимые предложения, не угадывая целевой объект заказчика;
- число кандидатов и время работы не являются метриками точности. Требуется отдельный экспертный эталон и замеры IoU/false snowable pixel rate.

Для случайного нового ракурса результаты неизбежно слабее, чем для фиксированной камеры с геометрией, размеченной один раз.

## Проверки

```bash
python -m unittest discover -s tests -p 'test_roof_detection_classic.py' -v
```

Имеются синтетические тесты для двух крыш, мансардного окна, отказа от узкой красной дорожной полосы, автоматического многокрышного экспорта и обратной совместимости предыдущих пяти этапов. На реальном `DJI_0315.jpg` проверены выполнение без нейросети и экспорт нескольких примеров, но **не пиксельная точность**.
