# Генератор кровель: пункты 1–7

Реализация находится в `roofcheck/roof/`. План ссылался на `src/snowcv`, но актуальный репозиторий использует пакет `roofcheck`. Существующий depth-first/3D генератор `roofcheck/synth.py` сохранён. Новый конвейер предназначен для произвольных фотографий с явно заданными масками, без MoGe, парковочной геометрии и предположения о физической толщине снега.

## Вход и запуск

Минимальные зависимости: NumPy, SciPy, Pillow, OpenCV. Полная установка моделей проекта для этого конвейера не требуется.

    python -m pip install numpy scipy pillow opencv-python-headless
    python -m roofcheck.roof sample.json --output out/roof-example --seed 42

Пример `sample.json`:

```json
{
  "sample": {
    "image_id": "frame_001",
    "image_path": "image.jpg",
    "group_id": "building_001",
    "split": "train",
    "roof_mask": "roof.png",
    "snow_mask": "snow.png",
    "inspection_roi": "roi.png",
    "occluder_mask": "occluders.png",
    "annotation_mode": "partial",
    "mask_coordinates": "oriented",
    "source": "expert-reviewed customer archive",
    "surfaces": [
      {"surface_id": "slope_1", "mode": "approximate", "texture_scale": 24}
    ]
  },
  "generation": {
    "scenario": "partial_cover",
    "target_coverage": 0.45,
    "coverage_tolerance": 0.02,
    "alpha_low": 0.01,
    "alpha_high": 0.85,
    "edge_px": 1.0,
    "texture_strength": 0.025
  }
}
```

Пути во входном JSON разрешаются относительно самого JSON. Необязательные файлы можно убрать. Зона генерации — `roof_mask`, а ROI ограничивает только расчёт показателей. При нескольких крышах маска должна включать только выбранные поверхности.

`annotation_mode`:

- `partial`: нужна имеющаяся маска 0/1/255; без маски всё неизвестно, а не чисто.
- `full`: нужна маска без неизвестных пикселей, полностью размеченная сцена.
- `verified_clean`: без маски нули назначаются только видимой кровле; остальная сцена остаётся неизвестной. С маской положительные снежные метки запрещены.

Фото приводится к EXIF-ориентации. `mask_coordinates=raw` означает, что к маскам применяется та же ориентация. При `oriented` маски уже должны соответствовать повёрнутому фото. Неоднозначное автоматическое угадывание по размерам не используется. Полигоны/геометрия всегда задаются в ориентированном фото.

Снежная маска: uint8 PNG, 0=не снег, 1=снег, 255=неизвестно. Маски поверхности, ROI и препятствий: 0/1 или 0/255. Ошибочные размеры/классы отвергаются. Снежную маску 0/255, где белое означает снег, необходимо перекодировать явно.

## Восемь сценариев

| Сценарий | Форма | Покрытие по умолчанию |
|---|---|---|
| sparse_patches | Несколько нерегулярных пятен | 0.06 |
| scattered_patches | Много небольших участков | 0.18 |
| partial_cover | Частичное покрытие по многоуровневому полю | 0.45 |
| near_full_cover | Почти сплошное покрытие с просветами | 0.92 |
| edge_residue | Остатки у границ поверхности | 0.08 |
| cleared_irregular | Неровная граница очищенной полосы | 0.35 |
| thin_streaks | Узкие вытянутые полосы | 0.12 |
| shadowed_snow | Предпочтение затенённым частям | 0.40 |

`target_coverage` можно переопределить, включая 0 и 1. При 0 фото и исходная маска сохраняются без изменений. Это отрицательный по **добавленному** снегу пример: если снег уже был, итоговое изображение не является отрицательным.

Сценарий задаёт поле предпочтения, а не строгую гарантию числа компонентов: после ограничения сложной поверхностью или препятствиями компоненты могут разделяться. Их фактическое число фиксируется. `near_full_cover` использует тот же тип поля, что partial, с другой долей покрытия. Реализм и диапазоны параметров требуют дальнейшей калибровки по реальным фото.

## Покрытие и границы

Все случайные поля создаются один раз. Выбирается фиксированное число пикселей с наибольшим значением поля. Случайности внутри подбора порога нет. Пространственные операции, меняющие площадь после выбора, не применяются к уверенной сердцевине.

`target_coverage`, `generated_coverage` и `final_visible_coverage` относятся к **добавленному уверенному снегу / разрешённым видимым пикселям кровли без исходного снега**. Это мера управления генерацией, поэтому в ней учитываются также исходно неизвестные пиксели, которые можно уверенно перекрыть снегом.

Для общей доли снега отдельно записываются `roof_total_snow` и `inspection_total_snow`: из их знаменателя исключаются неизвестные пиксели, рядом сохраняются число известных и неизвестных. Исходный снег учитывается в итоговой доле. Дополнительно фиксируются число добавленных пикселей вообще и внутри ROI. Пустой знаменатель итоговой доли даёт `null`.

Переходная полоса вокруг уверенного снега имеет промежуточную непрозрачность и получает 255. Исходный снег, препятствия и области вне кровли полностью защищены. После рендеринга снова применяются ограничения поверхности; точные исходные RGB-пиксели защищённых областей восстанавливаются. Если финальная доля не укладывается в допуск (в том числе из-за размера пикселя), пример отвергается.

## Геометрия

У каждой поверхности уникальный `surface_id`, необязательный `polygon`, порядок `z_order` и `texture_scale`.

- `image`: режим C, координаты изображения. Перспективный и метрический масштаб неизвестны.
- `approximate`: режим B, заданный четырёхугольник `quad` в порядке TL,TR,BR,BL; без него оценивается четырёхугольник границы маски. Для сложного контура применяется ограничивающий прямоугольник, что явно отмечается в метаданных. Это приближение по разметке, не восстановление камеры по фальцам.
- `homography`: режим A, явно заданные `grid_to_image` (3×3) и `grid_size` [width,height]. Физические единицы не предполагаются: пользователь определяет масштаб сетки.

Для нескольких скатов задаются отдельные полигоны и преобразования. Геометрия должна покрывать всю маску кровли; незаполненные области и вырожденные преобразования отвергаются. В перекрытиях побеждает поверхность с большим z_order (при равенстве — более поздняя во входе). Текстуры используют перспективную выборку с mip-уровнями по локальному масштабу. Согласование масштаба соседних скатов задаётся их сетками/texture_scale, автоматическая метрическая калибровка отсутствует.

## Выход

- `image.png`: результат без повторного JPEG-сжатия, чтобы защищённые пиксели совпадали точно.
- `mask.png`: обучающая маска 0/1/255 с проверкой после повторного чтения.
- `alpha.png`: финальная непрозрачность uint16, диапазон 0..65535; диагностический файл, не классовая маска.
- `source.<расширение>`: побайтовая копия оригинала, включая EXIF.
- `metadata.json`: seed, конфигурация, входные данные, геометрия, показатели покрытия, SHA256 входных файлов и реализации.

Готовая директория создаётся через временную и не перезаписывается молча. Пакетный манифест, SQLite, возобновление, полноценный QA и абляционное обучение относятся к последующим пунктам плана.

## Проверка

    python -m unittest discover -s tests -p 'test_roof_generator.py' -v
    python tools/demo_roof_generator.py

Демонстрация создаёт искусственную тестовую сцену, все сценарии и контактный лист в `out/roof_demo/`. Это проверка геометрии и контрактов, не доказательство фотореализма на рабочих кровлях. Для такой проверки нужны фотографии с экспертными масками поверхности и перекрытий.

Из legacy исправлены 0/1/255 экспорт, неоднозначность slush и фиксированное случайное поле для порогового поиска. Старый парковочный прототип остаётся экспериментальным: новый контракт восстановления препятствий обеспечивается конвейером `roofcheck.roof`. В действующем `synth.labels_at` дополнительно исправлена ошибка: нулевая толщина больше не попадает в ignore из-за полосы ±1 около порога 1 мм. Геометрическая толщина старого рендерера не становится измерением реальной толщины по фото.
